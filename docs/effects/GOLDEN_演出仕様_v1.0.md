# GOLDEN 演出仕様 v1.0（リールフラッシュ・ロゴランプ）

作成日：2026-10-15
対象：tarutoon7391/golden-slot フェーズ8b（器）・8c（抽選接続）
前提：リーチ目仕様 v1.1、probability.ts の現行テーブル（BONUS_SPLIT：チェリー22%・スイカ13%・リーチ目A/B 各5%・残り単独）

---

## 0. 設計思想

- フラッシュもランプも **小役の予告** であって、ボーナスの告知ではない。「予告した小役が揃わなかった（否定）」でボーナスを察知する。
- 否定はリール停止で起きる。フラッシュは第3停止の直後に出るが、それ自体はボーナスを確定させない（チャンス系の例外あり）。
- ランプはレバーONでは何も出ない。停止ボタンを押すたびに1個ずつ点き、「何個目まで点いたか」で候補の小役が絞られる。
- 期待度は「小役の成立頻度」と「ボーナス成立後の滞在頻度」の比で決まる。リプレイ・ベルは成立が多いので期待度が低く、スイカ・チェリーは高い。
- 演出はボーナス消化中（BIG・REG中）には出さない。
- **ハズレ（小役もボーナスも成立していないゲーム）では、フラッシュもランプも絶対に出さない。** したがって「何か出たのに小役が揃わなかった」は、ボーナスか取りこぼし（スイカ・チェリー）のどちらか。取りこぼしの曖昧さはリーチ目で解消する（スイカF＋取りこぼしリーチ目＝確定）。リプレイ・ベルは取りこぼさないので、リプレイF・ベルF・1点灯のみ（ベル候補）が否定された時点で確定。

## 1. 器（フェーズ8b）

### 1.1 リールフラッシュ 6種（色なし、白〜金の単色）

| ID | 名前 | 動き | 目安時間 |
|---|---|---|---|
| REP | リプレイF | 3リール同時に、下段→中段→上段へゆっくり光が上がる | 500〜600ms |
| BELL | ベルF | 中央（中リール中段）以外の8コマが、時計回りに1周光る | 500ms |
| MEL | スイカF | 右上（右リール上段）から左下（左リール下段）へ、剣で斬るように一直線に速く光る | 200〜250ms |
| CHER | チェリーF | 左リールのみ、上段→中段→下段へゆっくり光が下りる | 500〜600ms |
| CMEL | チャンススイカF | 右上と左上から同時に、斜め下へ剣で斬るように速く光る（X字） | 250ms |
| CCHER | チャンスチェリーF | 左→中→右の順に、各リールが下段→上段へ速く光る | 300ms（1リール100ms） |

- 発生タイミング：**第3停止（最後のストップボタン）の直後**。抽選自体はレバーON時に済ませておき、全停止で出す。（2026-10-15 変更。当初はレバーON直後・回転開始と同時）
- 実装：リール窓の各コマに当てる CSS クラス（`flash-cell`）と、6種の keyframes。JS はクラスの付け外しとタイマーだけ。
- 型：

```ts
type FlashId = 'REP' | 'BELL' | 'MEL' | 'CHER' | 'CMEL' | 'CCHER';
interface FlashRequest { id: FlashId }   // null なら発生なし
```

### 1.2 ロゴランプ GO / LD / EN

- 対応：**左リール＝GO、中リール＝LD、右リール＝EN**。止めたリールのランプが点く。
- レバーON時点で内部的に「点灯数 N ∈ {0,1,2,3}」を決める。第k停止（k ≤ N）で、そのとき止めたリールのランプを点ける。k > N では点けない。
- 例：N=2 で挟み打ち（左→右→中）なら、GO → EN が点き、LD は暗いまま。
- 点灯は次のレバーONまで保持し、レバーONで全消灯。
- 型：

```ts
interface LampPlan { count: 0 | 1 | 2 | 3 }
// 停止処理側：history.length <= plan.count なら、止めたリールのランプを on
```

### 1.3 デバッグパネル

- 6種のフラッシュの試し撃ちボタン
- ランプ GO/LD/EN の個別 on/off と「点灯数を指定してレバー」ボタン
- 直近ゲームの「成立役・ボーナスフラグ・引いたフラッシュ・点灯数」を表示

## 2. 抽選（フェーズ8c）

### 2.1 抽選のタイミングと入力

レバーON時、役抽選の直後に1回。入力は `(成立役, ボーナスフラグ)`。

| 状態キー | 意味 |
|---|---|
| N/役 | 通常時（フラグなし）にその小役が成立 |
| B/none | ボーナス成立後（当選G・持ち越しG）で小役なし（単独当選・リーチ目役・ハズレ） |
| B/役 | ボーナス成立後にその小役が成立（当選Gの重複、または持ち越し中の成立） |

ハズレ（N/none）は何も出さない。

### 2.2 フラッシュ表（発生率、残りは「なし」）

| 状態 | REP | BELL | MEL | CHER | CMEL | CCHER |
|---|---|---|---|---|---|---|
| N/リプレイ | 50% | | 2% | | | |
| N/ベル | | 50% | | | | |
| N/スイカ | | | 60% | | 6.7% | |
| N/チェリー | | | | 50% | | 5.8% |
| B/none | 7.5% | 6% | 12% | 10% | 3% | 3% |
| B/リプレイ | 15% | | 85% | | | |
| B/ベル | | 30% | | | | |
| B/スイカ | | | 5% | | 90% | 5% |
| B/チェリー | | | | 5% | 5% | 90% |

読み方の例：
- N/スイカ で CMEL 6.7%、B/スイカ で CMEL 90% → 「チャンススイカF が出てスイカが揃った」のうち約半分がボーナス。
- B/スイカ で CCHER 5% → 「チャンスチェリーF が出てスイカが揃った」は B/スイカ でしか起きないので確定。
- B/チェリー で CMEL 5% → 同様に「チャンススイカF でチェリー」は確定。
- B/none の合計 41.5%。成立後で小役がないゲームの4割でフラッシュが出て、必ず否定される。

- 3点灯：リプレイ・スイカ・重複チェリー・重複スイカ（ごく一部）

### 2.4 B/none のときのフラッシュとランプの整合

B/none ではフラッシュと点灯数を独立に引くと「ベルF＋2点灯」のような、停止前に矛盾する組み合わせが出る。これを避けるため、**フラッシュを先に引き、点灯数はそのフラッシュと矛盾しない集合から引く**（2.3 の B/none 行を、許される点灯数だけに正規化して使う）。

| 引いたフラッシュ | 許される点灯数 |
|---|---|
| なし | 1・2・3 |
| REP | 1・2・3 |
| BELL | 1 のみ |
| MEL | 1・2・3（リプレイの可能性があるため） |
| CHER | 1・3 |
| CMEL | 1・2・3 |
| CCHER | 1・3 |

N/役・B/役 は両方とも実際の成立役から引くので、矛盾は構造上起きない。

## 3. 停止ごとの情報（プレイヤー向けの読み方、実装には不要）

- 第1停止で点灯：ハズレ否定。候補は全小役
- 第2停止でも点灯：ベル・単独チェリー・単独の重複スイカの大半が消える → リプレイ・スイカ・重複チェリー
  - 左にチェリーが見えているのに第2停止で点いた → 重複チェリー確定
  - 左ベル中段で第2停止で点いた → 確定
- 第3停止でも点灯：リプレイ・スイカ・重複チェリー・（ごく一部）重複スイカ
- どの段階でも、点いた状態で候補の小役がどれも揃わなければボーナス
