# GOLDEN（仮称）– ブラウザで遊べる Aタイプ・パチスロゲーム

React + Vite + TypeScript で作るオリジナルのパチスロゲームです。
仮想コインのみで遊ぶゲームで、換金・課金など実在のお金に関わる要素は一切ありません。

機種名は仮称です。`src/config/machine.ts` の `name` を変えると全画面の表示が切り替わります。

## 必要なもの

- Node.js 22.18 以上（`node scripts/sim/run.ts` のように TypeScript を直接実行するため）

## npm scripts

| コマンド | 内容 |
| --- | --- |
| `npm run dev` | 開発サーバー起動（<http://localhost:5173>） |
| `npm run build` | 型チェック + 本番ビルド（`dist/` に出力） |
| `npm run preview` | ビルド結果をローカルで確認 |
| `npm test` | Vitest で単体テストを実行 |
| `npm run sim` | シミュレーター。`-- --setting 3 --games 1000000 --seed 42` で設定・ゲーム数・シードを指定（既定: 全設定・各1000万G） |
| `npm start` | `dist/` を静的配信（Railway 用。環境変数 `PORT` を使う。未設定なら 3000） |

## 遊び方

- **PC**: MAXBET = `1` / `B` / `↑`、レバー = `Enter` / `Space` / `↓`、ストップ = `←` `X` `→`（または `Z` `X` `C`）、やめる = `Esc`。割り当ては `src/config/keys.ts`
- **スマホ**: ボタンをタップ
- 設定（1〜6）はゲーム開始時に重み付きランダムで決まり非公開。「やめる」で設定発表と、データからの推測結果が出る
- 進行状況は localStorage に自動保存され、再読み込みしても続きから遊べる
- 仮想コインが足りなくなったら「コインを追加」で補充できる（仮想）

## デバッグモード（`?debug=1`）

URL に `?debug=1` を付けると筐体の下にデバッグパネルが出る（例: `http://localhost:5173/?debug=1`）。

- **内部状態**: 設定・乱数シード・今ゲームの抽選結果（乱数値・強制フラグ）・持ち越し・引き込み対象・演出計画・払い出し判定
- **当選役の強制**: 次ゲームの抽選結果をハズレ／各小役／BIG7・BIGG・REG（単独・チェリー・スイカ・リーチ目役A・B の重複）に固定（1 ゲームだけ、または毎ゲーム）
- **設定・シードの固定**: 今の台の設定を変える、「新しい台で始める」時の設定を固定する、乱数シードを指定して乱数列をやり直す
- **押下位置の指定**: 各リールの押下コマ番号を 1〜21 で指定（空欄は通常どおり押した時刻から）。回転アニメーション・ウェイト・払い出し表示のスキップ
- **停止制御の候補**: 止めたリールごとに 0〜4 コマの候補と、ルール別の ○ accept／× reject／− neutral、理由、除外したルール、使ったルールセット（内部状態にも「制御セット」として表示）
- **リーチ目**: 今の出目に一致する `src/config/reachme.ts` のパターン（押し順・押下位置・スベリの条件込み。出目だけ一致で条件が合わないものは別に表示。空なら「テーブルは空」）。「出目をコピー」で今の出目を reachme.ts の書式で取得できる
- **制御込みシミュレーション**: 設定とゲーム数を指定し、実際の停止制御と払い出し判定を通して機械割などを理論値（`npm run sim` と同じ計算）と並べて表示。押し方は「目押しあり（当選役を狙う）」「ランダム（目押しなし）」「順押し固定」。同じシードなら抽選の乱数列は理論値と同じなので、差は制御だけで生じる（目押しありなら理論値と一致する）

デバッグパネルは表示と差し込みだけで、抽選・制御・判定のロジックは一切持たない。処理順（内部抽選 → リール制御 → 演出）も変わらない。

## 仕様メモ

- ボーナスは 3 種。BIG7（赤7・赤7・赤7、300 枚）、BIGG（G・G・G、300 枚）、REG（赤7・赤7・BAR、100 枚）。BIG7 は設定差なし、BIGG・REG に設定差
- REG の 赤7・赤7・BAR は右下がり（左上段・中中段・右下段）だけ有効。上段・中段揃いは配列上リプレイが、下段・右上がりは代用スイカ（ス・ス・BAR）が同時に揃うため無効
- チェリーは左リールの角（上段・下段）のみ入賞（4 枚）。左中段チェリーは入賞せず、リーチ目役B の形
- リーチ目役A（上段 BAR 揃い）・リーチ目役B（左中段チェリー）は配当 0 の小役。ボーナス当選ゲームにだけ重複し（各 5%・`BONUS_SPLIT`）、持ち越し中は抽選しない。非当選時はリール制御がこの形を止めない
- 確率は `src/config/probability.ts` の `BONUS_TOTAL`（ボーナス 3 種 × 設定）と `SMALL_WEIGHTS`（小役 × 設定）で決める。機械割は設定 1 ≈ 97.6% 〜 設定 6 ≈ 109.2%（`npm run sim`）

- 小役の取りこぼしなし（ベル・リプレイ 100% 引き込み）は順押し・挟み打ちで保証する。中→左→右はベル 99.6%（リーチ目回避の影響で 32/9261 押下位置だけ取りこぼす）。右先押しは保証しない（右先押し時のベル取りこぼし約 8〜10% は仕様として受け入れる）。
- スイカ・チェリー・ボーナス図柄は目押し役。適当に押すと取りこぼす（ランダム押しでスイカ約 6 割・チェリー約 5 割の入賞）。
- リーチ目は `src/config/reachme.ts` に 153 件（仕様書 §3 の R01〜R12・S01〜S06・G01〜G07。R04・R11 は生成）。ハズレ・リプレイ・チェリー・ベルでは全押し順 × 全押下位置（277,830 ゲーム）で 1 件も出ないことを `node scripts/probe/reachme.ts` と test/reachme.test.ts で検算している。スイカ成立時だけは、仕様 v1.2 P1 補足の形（R04・R09・R10・G02〜G04・G07・S03〜S06、`viaForPullIn`）を「それ以外では取りこぼし確定」のときに経由して引き込むので、目押しを外すとその形が残ることがある（約 1% のゲーム）。ボーナス成立中は、ボーナスが揃わなければ約 8〜9 割がリーチ目になる
- ボーナス成立中に他系のリーチ目（BIG7 中に G 系など）は原則出ないが、REG 成立中の 右→中→左 で右 10〜14 番・中 19 番・左 4 番押しの 5 通りだけ、左が 8 番（G 上段・4 コマスベリ＝G04 の形）に止まる逃げ場なしの形がある（他の候補がスイカ・チェリーの非当選入賞になるため）

## Railway へのデプロイ

静的ファイルを `scripts/server.mjs` で配信するだけなので、データベースや環境変数の設定は不要。

1. GitHub にこのリポジトリを push する
2. Railway で **New Project → Deploy from GitHub repo** を選び、`golden-slot` を選ぶ
3. サービスの **Settings** で次を確認する（`package.json` から自動検出されるはずだが、違っていたら手で入れる）
   - Build Command: `npm run build`
   - Start Command: `npm start`
   - Node のバージョンは `package.json` の `engines`（22.18 以上）から決まる。古い Node が選ばれてビルドが失敗したら、Variables に `NIXPACKS_NODE_VERSION=22`（または Railpack なら `NODE_VERSION=22`）を足す
4. `PORT` は Railway が自動で注入する。サーバーはそれを読んで待ち受ける（未設定なら 3000）
5. **Settings → Networking → Generate Domain** で公開 URL を作る
6. 公開 URL を開いて、リールが回る・音が鳴る・`?debug=1` でデバッグパネルが出ることを確認する

以後は main ブランチへ push するたびに自動で再デプロイされる。

ローカルで本番と同じ配信を試すには:

```sh
npm run build
npm start          # http://localhost:3000
```
